# List, task, and code rendering

List styling keeps bullets, checkboxes, native guides, and nested code aligned while preserving editable Markdown and native controls.

## Sub-features

- `render-lists`: styled unordered/ordered markers, nesting, wrapping, and theme-derived appearance.
- `render-threading`: optional colored connections from the current item to its ancestors, with independent paths in each editor and no threading extension while disabled.
- `render-tasks`: an independent task bullet for zoom/drag beside the native checkbox; checked styling must not strike through the bullet.
- `render-code`: nested code in native preview, editing, and Shiki preview, with stable background bounds, spacing, guide alignment, and horizontal reach.
- `render-code-frames`: respect Shiki Frame settings and explicit titles, keeping headers visible and code glyphs aligned through preview/editing transitions.
- `render-code-shapes`: empty/blank-first blocks, alternate fences, language labels, deep nesting, wrapping, and blocks whose opening fence is offscreen.
- `render-code-input`: native typing and Vim navigation/newlines stay inside source code; copy preserves code indentation without list prefixes.

## How to get to it (user POV)

- Enable **Settings → Bullet → Appearance → Style list bullets**. Open nested unordered/ordered/task lists in Live Preview; toggle the setting, switch to Source mode, and reload Bullet.
- Enable **Bullet threading** in Appearance and choose **Thread color**. Click list text to follow a different branch. Threading is off by default.
- Click or tap `.task-list-item-checkbox` to complete a task, the separate `.bullet-plugin-task-bullet` to zoom, or its bullet to drag on desktop. Use a task's native `.collapse-indicator` independently.
- Put a fenced block inside an item or a list continuation. Move the cursor into/out of code to switch between editing and preview; scroll through short repeated blocks or one long block.
- With the installed Shiki Highlighter plugin, test disabled, enabled without line numbers, and enabled with line numbers. In **Settings → Shiki Highlighter → Frame**, compare **Auto**, **None**, **Code**, and **Terminal**. Auto chooses terminal headers for shell languages; an explicit title can add a header to other languages. None removes headers. Use the native code copy control; enable Vim and use `j`, `k`, `o`, and `O` for navigation/newlines, then `0`, repeated `h`, and `i` followed by text to check editable left edges.

## Driving it with Obsidian CLI/CDP

Preconditions: use the parent lifecycle and index guards. Enable list styling for task-bullet and code-layout recipes; threading is independent of list styling. Scripts that toggle Shiki require an installed Shiki fixture. Each output directory must be fresh. Geometry scripts generally place cursors and change settings through APIs; that setup does not prove clicks or typing.

- **Native preview hover and opening-row height:** `n exec 22.23.1 node scripts/verify-nested-code-hover.cjs "$PROOF_DIR/code-hover"` requires installed Shiki and list styling. It enables Shiki, switches preview → editing → preview by API cursor placement, and sends hit-tested native pointer movement. Require a positive opening-fence height equal to its code line height, no preview box shadow on hover, available edit/copy controls, and unchanged Markdown. Inspect all three PNGs and `results.json`. This does not click the controls, type, toggle line numbers, or cover Shiki-disabled preview.

- **Shiki frames, languages, and titles:** `n exec 22.23.1 node scripts/verify-code-frame-parity.cjs "$PROOF_DIR/code-frames"`, then repeat with a fresh path and `--light`. Require 45 results with zero failures per run across Auto/None/Code/Terminal and `sh`, `bash`, `zsh`, `powershell`, `js`, `ts`, `python`, `json`, and unlabeled fences, plus numbered title/font variants at 16/24/30. Require positive native fence rows, stable code glyph origins through preview → editing → preview, retained titles, visible unclipped header paint, copy-button hit targets, code-only `data-code`, and unchanged saved Markdown. Subtract the measured line-number gutter when comparing horizontal origins. Inspect terminal/title PNGs. Settings and cursor transitions use APIs; `--light` changes renderer theme classes. This does not click copy or check the OS clipboard. Compact header alignment requires browser support for `overflow-clip-margin`; unsupported browsers retain full header height.

- **Native task actions:** `n exec 22.23.1 node scripts/verify-task-bullets.cjs "$PROOF_DIR/task-bullets"` and separately `n exec 22.23.1 node scripts/verify-task-bullets.cjs "$PROOF_DIR/task-bullets-mobile" --mobile`. These hit-test and send real mouse/touch input. Require separate bullet/checkbox hit boxes, checkbox `[ ]`/`[x]` changes without zoom, bullet zoom without Markdown changes, wrapped alignment, native Undo/Redo, folded-task controls, and desktop-only task dragging. Source/style/reload transitions use APIs. Mobile mode is actually toggled.
- **Bullet threading:** `n exec 22.23.1 node scripts/verify-bullet-threading.cjs "$PROOF_DIR/threading"`. This uses native mouse input for the settings toggle, item selection, checkboxes, and fold controls, plus native typing while disabled. Require exact painted ancestor endpoints, including unordered and ordered attached-code blocks through native/Shiki/numbered toggles, editing, preview return, and zoom. Renderer toggles retain the same selection. Require wrapped-parent alignment, a clipped path when a compatible parent marker is above the rendered viewport, independent panes, operation with list styling disabled, and no layer while disabled. Offscreen continuation requires matching raw markers and task shape; incompatible shapes omit the continuation. Color, list styling, Source mode, zoom, and reload use APIs. Inspect saved screenshots. This desktop recipe does not certify mobile or native color-dialog interaction.
- **Painted bullets and Vim editing origins:** `n exec 22.23.1 node scripts/verify-nested-code-positions.cjs "$PROOF_DIR/code-positions"` switches the same document between preview and editing through API cursor placement. It covers multiline, empty, and blank-first blocks with Shiki disabled, enabled, and numbered. Require stable horizontal bullet paint positions, vertical alignment with the first code line, and restoration of the original position after returning to preview. The visible source fence can expand the opening row during editing; the bullet must move by exactly that expansion. Empty-block markers must stay within the card. Verify native bullet zoom and chevron fold/unfold targets. Native `0`, five `h` presses, and `i` followed by text must give opening, body, and closing rows the same painted left edge, preserve the exact container prefix, and match saved Markdown. Measure translated bullet pseudo-element paint, not only the source-bearing span. Ordered numbers intentionally align only in preview. Use the parity check below to measure top whitespace.
- **Preview/editing geometry:** `n exec 22.23.1 node scripts/verify-nested-code-layout.cjs "$PROOF_DIR/code-layout" --long`. Repeat in native, Shiki, and numbered Shiki states using fresh paths. It moves the cursor and edits through editor APIs; require native marker/guide alignment, correct `.cm-preview-code-block` bounds, expected Markdown, and stable top/bottom viewport cases. It is not native typing proof.
- **Spacing and adjacent-block parity:** `n exec 22.23.1 npm run test:code-parity -- "$PROOF_DIR/code-parity"` and `n exec 22.23.1 node scripts/verify-nested-code-spacing.cjs "$PROOF_DIR/code-spacing"`. Both compare native, Shiki, and numbered modes. Parity measures the distance from the painted card top to the first visible code or fence glyph and requires normal top padding, plus the expected gap between adjacent cards. Compare glyph positions between renderers in the same editing phase. Spacing allows only the height added by visible source-fence text when switching to editing; code-row heights and native guide hit boxes remain valid.
- **Blank, alternate-marker, and live-setting shapes:** begin with Shiki installed but disabled, then run `n exec 22.23.1 node scripts/verify-nested-code-matrix.cjs "$PROOF_DIR/code-matrix"`. It toggles processors/settings on the same open note. Require unchanged Markdown and correctly aligned blank-first, ordered, tilde/four-backtick, deep, framed, and wrapped blocks.
- **One long offscreen block:** run `n exec 22.23.1 node scripts/verify-nested-code-long-block.cjs "$PROOF_DIR/code-long"`; repeat with fresh paths and `--blank-viewport`, `--blank-viewport --zoom-parent`, and `--blank-viewport --partial-zoom`. Use native/Shiki/numbered states as applicable. Require visible code backgrounds/guides when the opening fence is offscreen or only blank rows are visible. The many-short-block `--long` layout case is a different test.
- **Redraw and first appearance:** `n exec 22.23.1 node scripts/verify-nested-code-redraw.cjs "$PROOF_DIR/code-redraw"` and `n exec 22.23.1 node scripts/verify-nested-code-first-paint.cjs "$PROOF_DIR/code-first-paint"`. These use empty editor updates or programmatic scrolling and capture frames. Require persistent code backgrounds, stable glyph/scroll positions, horizontal reach, and complete layout at the first host-classified code frame. They do not send repeated native typing.
- **Width and indentation/copy data:** `n exec 22.23.1 node scripts/verify-nested-code-width.cjs "$PROOF_DIR/code-width"` checks fitted painted width and literal indentation across tabs/partial tabs, empty/wrapped/offscreen rows, and editing/preview.
- **Shiki source and copy-payload normalization:** `n exec 22.23.1 node scripts/verify-nested-code-preview-indent.cjs "$PROOF_DIR/code-indent"` covers attached fences and ordinary/task continuation fences, including deep nesting and partial tabs. Titles containing `preserveIndent` or `hangingIndent` must not become wrapping options. With line numbers off/on, require all 192 samples to preserve source Markdown and match code-only display/copy data through preview, editing, reconfiguration, style toggles, and reload. The driver reads `data-code`; it does not exercise the OS clipboard or native paste.
- **Mobile code-fold controls:** use the [mobile preview and focused-source recipes](guides-and-folding.md) for right-edge placement, full touch height, painted bullet alignment, and actual fold/unfold taps. This narrow mobile proof does not certify general mobile code rendering.
- **Native code input/navigation:** `n exec 22.23.1 node scripts/verify-nested-code-interactions.cjs "$PROOF_DIR/code-input"` types code with CDP input before its painted-marker, drag, and paired-history checks. See the [drag map](desktop-drag-and-drop.md) for renderer and zoom variants. `n exec 22.23.1 node scripts/verify-vim-code-navigation.cjs "$PROOF_DIR/code-vim-nav"` sends native `j`/`k` across source/fence rows, including root and nested ordered/unordered blocks, with Shiki off/on. Repeat with fresh paths and `--font=24` and `--font=30`; a compact opening row that works at the default font size can skip rows at larger sizes. The script checks the applied font size and restores the original setting. `n exec 22.23.1 node scripts/verify-vim-code-newlines.cjs "$PROOF_DIR/code-vim-newlines"` sends `o`/`O` then text. Require exact source/cursor results and no skipped rows or invented bullet inside code.
- **Native gaps:** focus visible code through a real click, type repeatedly near a nested block with `Input.insertText`, and record caret screen Y, `scrollTop`, glyph/marker/background bounds, and Markdown after each received input. Locate the native copy control in `.code-block-flair`, or Shiki's `button[data-code]`; click after hit testing and compare the actual OS clipboard with code-only indentation. Separately paste into a scratch note and verify saved Markdown; clipboard equality alone does not prove paste. Preserve and restore the original clipboard representations without logging them. Test theme/list-style changes and ordinary ordered/unordered wrapping through their actual settings UI; API-renderer checks do not certify those entry points.

- **Painted code-guide seams:** `n exec 22.23.1 node scripts/verify-code-guide-seams.cjs "$PROOF_DIR/code-guide-seams"` uses the reported nested code fixture with a whitespace-only body row and an empty following sibling. Require nine results with zero failures across native, Shiki, and numbered preview at font sizes 16, 24, and 30. Compare PNG guide-column brightness above, across, and below the seam to detect doubled translucent paint and dark gaps. Verify unchanged saved Markdown. This recipe sets up the cursor through editor APIs and measures preview paint, not native typing or guide clicks.

## Gotchas

- Task bullets apply to styled unordered tasks; use the native checkbox independently. Source mode intentionally exposes Markdown instead of the Live Preview task bullet.
- A physically blank code row still has a line box; an empty block still needs visible height. Equal block totals can hide wrong gaps or clipped first/last glyphs.
- Do not mistake a processor embed for native editable rows. Test native code and `.cm-preview-code-block` separately, including language-free and numbered cases.
- Only top-level metadata keys configure `preserveIndent` and `hangingIndent`; text inside titles or other delimited values does not. Unsupported or duplicate relevant option values conservatively leave processor content unchanged.
- Shiki state/line-number setup varies by script. Record the actual mode, restore it, and report a missing plugin fixture as an unmet precondition, not a passing native case.
- These desktop code-layout scripts do not certify mobile code rendering, arbitrary themes, repeated native typing, or every copy-button hit target.
